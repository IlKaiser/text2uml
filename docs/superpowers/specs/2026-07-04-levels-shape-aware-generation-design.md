# Shape-aware complexity-level generation for the full case corpus

Status: approved for planning
Date: 2026-07-04
Owner: samuele.rinaldi90@gmail.com

## Problem

`experiments/levels/` compares few-shot UML generation across four description
complexity levels per case: `zero` (L0, minimal), `one` (L1, simple), `two`
(L2, mid), `three` (L3, the real/original spec). Today:

- All 45 dataset cases already have `description_level_one.md` and
  `description_level_two.md`, generated by `text/rewrite/run.py`, which drives
  each toward an aggregate `z_index` target (`level_one_target = 0.0`,
  `level_two_target = actual_z * 0.5`) using an iterative Claude rewrite loop
  (`text/rewrite/loop.py`) with a meaning-preservation verifier
  (`text/rewrite/verifier.py`).
- Only two cases — `GasStation_KUL` and `GasStation_TUW` — have a
  `description_level_zero.md`. Both are near-identical structured "Classes /
  Relationships" UML analyst-notes (not narrative prose), authored/generated
  outside the current pipeline.
- `experiments/levels/config.py` already declares all four levels (tags,
  filenames, ranks) and `case_pipeline.py` already supports a `zero` stage
  end-to-end for generation/evaluation/plotting — the only missing piece is
  the *description text itself* for `zero` on 43 cases, and a shape-consistent
  regeneration of `one`/`two`.

Inspecting the two GasStation references shows the four levels are not simply
"shorter = simpler." Per `text/output/complexity_metrics.csv`-derived
`z_index`: L0 ≈ L3 (both high) with L1/L2 much lower — a **valley shape**. The
aggregate z_index target used for L1/L2 today does not reproduce this shape
faithfully because it does not look at individual metrics; three metrics in
particular move in a very specific, mechanically-explainable way:

| Metric | GasStation_KUL (L0/L1/L2/L3) | GasStation_TUW (L0/L1/L2/L3) |
|---|---|---|
| `mdd` | 3.335 / 2.250 / 2.535 / 2.982 | 3.360 / 2.511 / 2.587 / 2.984 |
| `subordination_index` | 0.250 / 0.169 / 0.333 / 0.554 | 0.250 / 0.290 / 0.286 / 0.476 |
| `context_dependence_proxy` | 1.000 / 0.234 / 0.351 / 0.338 | 1.000 / 0.533 / 0.409 / 0.476 |

Reading `text/metrics/discourse.py` and `text/metrics/syntactic.py` explains
*why*: L0's structured-notes genre packs parenthetical multiplicities and
comma-appended participial clauses onto entities (raising `mdd` without
subordinating conjunctions), avoids subordinating cue words entirely (keeping
`subordination_index` low), and leans on pronouns (`it`, `its`, `they`) for
back-reference instead of repeating full entity names —
`ContextDependenceProxy` always counts personal/demonstrative pronouns as
unresolved, so a short, pronoun-heavy note drives this metric near its
ceiling.

**Goal**: regenerate `description_level_zero/one/two.md` for every case in
`dataset/` (except the two GasStation references, which stay as the
calibration source) so that these three metrics evolve across L0→L1→L2→L3 in
the same qualitative and roughly-quantitative shape as observed in
GasStation, verified by a closed feedback loop — both per-case (iterative
rewrite) and per-corpus (auto-retry any case whose resulting shape doesn't
hold).

## Non-goals

- Changing `description.md` (L3, the real spec) — never touched.
- Changing the few-shot UML-generation technique, evaluation/F1 scoring, or
  `case_pipeline.py`'s existing generate/evaluate/plots/correlate stages.
- A general-purpose "match arbitrary target shapes" framework — this is
  scoped to the three named metrics and the four existing levels.

## Target shape rules

Self-referential to each case's own (untouched) L3 metric values. Two layers:

1. **Rank constraints (hard gate)**, always required:
   - `mdd(L0) > mdd(L3)`
   - `subordination_index(L3)` is the max across all four levels
   - `context_dependence_proxy(L0)` is the max across all four levels
2. **Ratio bands (soft tightening)**, computed as the observed envelope
   across both GasStation cases with a small margin (not mean ± fixed
   tolerance, since n=2 and L1/L2 ratios vary meaningfully between the two
   references):

   | Metric | Level | Band (× that case's own L3 value) |
   |---|---|---|
   | `mdd` | L0 | ≥ 1.05× |
   | | L1 | 0.60–0.90× |
   | | L2 | 0.75–0.95× |
   | `subordination_index` | L0 | 0.35–0.65× |
   | | L1 | 0.20–0.70× |
   | | L2 | 0.45–0.75× |
   | `context_dependence_proxy` | L0 | ≥ 1.5× |
   | | L1 | 0.5–1.3× |
   | | L2 | 0.7–1.2× |

   A case with `z3` ≈ 0 for a metric (e.g. a description with zero
   subordinate clauses) makes ratio bands degenerate (0 × anything = 0); in
   that situation the rank constraint alone governs and the ratio band is
   skipped (logged, not treated as failure).

The existing aggregate `z_index` target (`level_one_target = 0.0`,
`level_two_target = actual_z * 0.5`) is kept as a coarse secondary signal
inside the feedback (steers overall direction) but is no longer the
acceptance criterion by itself.

## Architecture

### 1. Level-zero genre prompt (new)

New module `text/rewrite/structural_prompts.py` (sibling to `prompts.py`,
kept separate because it is a different genre, not a variant of the
linguistic-simplification prompt — mixing both into one 400+ line file would
violate the small-file convention). Contains:

- `structural_system_prompt()`: instructs the model to produce a "Classes /
  Relationships" UML analyst fact-sheet: enumerate entities with attributes,
  then relationships with multiplicities; pack qualifiers via commas/
  parentheses/participial appositions (not subordinating conjunctions); use
  pronouns for back-reference to already-introduced entities instead of
  repeating full names; preserve every fact from the source (same hard rules
  on information-preservation as the existing `system_prompt()`).
- Reuses `build_feedback`-style metric guidance (see below) for iteration.

### 2. Shape-aware feedback loop (generalizes `loop.py`)

Rework `rewrite_to_target` into a shape-aware variant (or add a parallel
`rewrite_to_shape` in `loop.py`) that, per iteration:

1. Scores the candidate with the existing `score_text` (unchanged — still
   need `z_index` as the coarse signal and `n_tokens` for the content-floor
   guard).
2. Additionally pulls `mdd`, `subordination_index`, `context_dependence_proxy`
   raw values from the scored candidate (already computed by
   `text.metrics.compute_all`; `ScoreResult.values` already carries every
   metric, so no new metric-computation plumbing is needed — just read three
   more keys).
3. Checks candidate values against that case's L3 rank + band rules for the
   level being generated (L3 values are precomputed once per case, since
   `description.md` never changes).
4. If all rank constraints hold and bands are satisfied (or degenerate/
   skipped), and the meaning verifier passes, and `z_index` is within the
   existing coarse tolerance: accept.
5. Otherwise, build feedback identifying exactly which metric(s) are out of
   band and in which direction, using concrete stylistic instructions (extend
   `_METRIC_GUIDANCE` in `prompts.py`, which already has entries for `mdd`,
   `subordination_index`, and a generic complexity-guidance shape;
   `context_dependence_proxy`'s existing guidance text — "make references
   explicit; avoid pronouns" — is the *opposite* of what L0 wants, so L0
   feedback must use an inverted instruction set specific to the structural
   genre. Keep the two guidance dicts separate: `_METRIC_GUIDANCE` for
   narrative simplification (L1/L2), a new `_STRUCTURAL_METRIC_GUIDANCE` for
   L0).
6. Same `min_token_ratio` content-floor guard and best-candidate tracking as
   today; same iteration cap (`max_iterations`, default unchanged at 5,
   configurable).

### 3. Config changes

`text/rewrite/config.py` (`RewriteConfig`): add `level_zero_name = "level_zero"`
and whatever knobs the shape loop needs (band table, tolerance margin already
above — likely hardcoded constants in the loop module itself, since they are
empirically derived and not meant to be casually overridden per run, similar
to how `_METRIC_GUIDANCE` is a module-level constant today).

### 4. Batch driver (extends `text/rewrite/run.py`)

Extend the existing CLI to also drive `level_zero` (currently only iterates
`level_one_name`/`level_two_name`). For every dataset (still skipping nothing
at this stage — GasStation cases get regenerated too for consistency, but
their result can be diffed against the hand-authored reference as a sanity
check), for each of the three levels in order zero → one → two:

1. Precompute/read that case's L3 (`description.md`) metric values once.
2. Run the shape-aware loop for the level.
3. Write `description_level_<name>.md`.
4. Record per-level: reached (rank+band OK), iterations, final metric values,
   which band(s) failed if not reached.

Append to a new summary CSV (`text/output/rewrite_shape_summary.csv`) instead
of overwriting today's `rewrite_summary.csv` schema, to avoid breaking any
existing consumer of that file.

### 5. Corpus-level closed loop (new)

New script `experiments/levels/shape_loop.py`:

1. Run the batch driver (step 4) for every case.
2. Recompute `experiments/levels/complexity.py`'s `compute_level_metrics` for
   the whole corpus (now all four levels populated everywhere) and write
   `levels_complexity.csv`.
3. For each case, re-check the rank+band rules directly from the freshly
   computed CSV (independent re-check, not just trusting the per-text loop's
   self-report — catches any drift from how the loop's own scoring vs. the
   corpus recompute might differ, e.g. spaCy model version).
4. Any case failing re-gates goes back through the batch driver for that
   specific level only, with feedback seeded from the failure reason, up to a
   configurable retry cap (default 2 extra corpus-level passes).
5. Stop when every case passes or the retry cap is reached; emit a final
   shape-compliance report: per case, per level, per metric — pass/fail,
   value, target band, iterations spent.

### 6. Regenerated outputs

- `dataset/<Case>/description_level_zero.md` (new for 43 cases)
- `dataset/<Case>/description_level_one.md`, `description_level_two.md`
  (regenerated for all cases, shape-aware this time)
- `experiments/levels/output/levels_complexity.csv` (refreshed, all cases now
  have all four levels)
- `experiments/levels/output/levels_complexity_matrix.{svg,png}`,
  `levels_zindex_matrix.{svg,png}` (regenerated via existing
  `experiments/levels/complexity.py`)
- Per-case `experiments/levels/output/case_metrics_<Case>.{svg,png}`
  (regenerated via existing `experiments/levels/case_metrics.py`)
- New `experiments/levels/output/shape_compliance_report.csv` (or `.md`) from
  the corpus loop
- `text/output/rewrite_shape_summary.csv` (new, batch driver run log)

## Error handling

- A case whose L3 has a metric value of 0 (degenerate ratio band): rank
  constraint still applies; ratio band skipped and logged, never fails the
  case on that account alone.
- Claude API failures during a single iteration: logged and the loop moves on
  with the best candidate so far, exactly as `rewrite_to_target` does today
  (no new behavior needed here).
- Corpus-level retry cap reached without full compliance: the run does not
  fail/raise — it finishes and reports the remaining non-compliant
  cases/metrics explicitly in the compliance report. A human decides whether
  to accept, hand-edit, or raise the retry cap and re-run.

## Testing

- Unit tests for the new rank+band check function (pure function over
  precomputed metric dicts — no API calls): cases include a clean pass, a
  rank failure, a band-only failure, and a degenerate (zero-valued L3 metric)
  case.
- Unit test for `_STRUCTURAL_METRIC_GUIDANCE` feedback text generation given
  a synthetic out-of-band `ScoreResult`.
- Integration-level smoke test (mocked Claude client) for one full pass of
  the shape-aware loop on a short synthetic description, asserting it
  terminates and writes a file.
- No test re-runs the real batch across all 45 cases (that is an operational
  run, not a test).

## Rollout

1. Implement the rank+band checker and structural prompt module with unit
   tests first (no API cost).
2. Dry-run (`--dry-run`, mirroring the existing flag) the batch driver against
   `GasStation_KUL`/`GasStation_TUW` only, comparing regenerated output's
   shape-check result against the hand-authored reference, as calibration.
3. Run the full batch across the remaining 43 cases.
4. Run the corpus-level closed loop / retry pass.
5. Regenerate plots and the compliance report; review with the user before
   considering the corpus "done."
