A smart home automation system (SHAS) lets users manage smart home tasks automatically. A smart home has a physical address. A smart home has many rooms. A room may hold sensor devices and actuator (controller) devices. Sensor devices and actuator devices have different types. Some types are temperature sensor, movement sensor, light controller, and lock controller. Each sensor has a unique device identifier. Each actuator has a unique device identifier. A user can turn a sensor or actuator on or off. When a user turns a sensor or actuator on or off, SHAS sees the change. Then SHAS updates the SHAS infrastructure map.

When SHAS is running, a sensor device gives sensor readings now and then. A sensor reading records the measured value. A sensor reading records the timestamp. In the same way, control commands go to the actuator devices. Each control command comes from a fixed set. Some commands are lockDoor and turnOnHeating. A control command has a timestamp. A control command has a status. The status can be requested, completed, failed, and so on. SHAS records all sensor readings for a smart home in an activity log. SHAS records all control commands for a smart home in the activity log.

The owner can set up and manage alerts in a smart home. The owner sets up alerts by making automation rules. An automation rule has a precondition. An automation rule has an action. The precondition is a Boolean expression. The precondition is made from relational terms. The relational terms join with basic Boolean operators (AND, OR, NOT). Atomic relational terms may point to rooms, sensors, actuators, sensor readings, and control commands. The action is a list of control commands. Here is a sample rule:

when actualTemperature by Device #1244 in Living Room < 18 and window is closed
then turnOnHeating in Living Room

Owners can create automation rules. Owners can edit automation rules. Owners can activate automation rules. Owners can deactivate automation rules. An owner can edit a rule only when the rule is off. A rule can depend on other rules. A rule can conflict with other rules. In this way, the owner can build a complex rule hierarchy. SHAS records each time an active rule fires. SHAS records each firing with a timestamp.
