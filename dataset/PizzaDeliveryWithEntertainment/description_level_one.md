A friend of yours is a hipster. He thinks he has the next billion-dollar startup idea. It is an app. The app is called Pizza Delivery with Entertainment. He heard that you follow a course on database management. So he asks you to design the UML class diagram. Later he will show the diagram to programmers. The programmers will build the app from it.

Your friend explains what the app does. Customers can order pizzas from restaurants. The app delivers the pizzas to a specific address. Customers can also choose a special "entertainment order". This choice is optional. For an entertainment order, the delivery person stays with the customer. This happens after delivering the pizza. Then the delivery person entertains the customers for a set amount of time. For example, the delivery person sings. Or makes jokes. Or does magic tricks.

Here is more detail about the app. People create an account. Then they become app users. Each user must give a birthday. Each user must give a name. Each user must give an address. Every user must be uniquely identifiable.

After the account is created, the user sees three options. The first option is "business owner". A business owner must also give a LinkedIn account. We use this account to add the business owner to our profession network. Every business owner can own many pizza restaurants. For each pizza restaurant, we register the zip code. We register the address. We register the phone number. We register the website. We register the opening hours.

Each pizza restaurant can offer many pizzas. For each pizza, we keep the name. The name can be margarita or quattro stagioni. We also keep the crust structure. The crust can be classic Italian crust, deep dish crust, or cheese crust. We also keep the price. Two pizzas from different restaurants may have the same name. But they are not exactly the same. The taste is different. So the app treats each pizza as unique. Two pizzas may also have the same price. The app still keeps them separate. For example, a pizza margarita from Pizza Pronto in New York costs $12. A pizza margarita from Pizza Rapido in Singapore also costs $12. The app must still keep these two pizzas separate.

The second option is "hungry customer". For each hungry customer, we need a delivery address. A hungry customer can make orders for pizzas. Each order gets an ID. The app logs the date and time of the order. The hungry customer can also give the latest time of delivery. We ask how many people the order is for. An order can be for one or more pizzas.

There is also a special type of order. It is called the entertainment order. Not every order is an entertainment order. Sometimes a hungry customer wants to be entertained while eating. In that case, we register all the regular order information. We also register the type of entertainment the customer wants. And we register how long the entertainment lasts. This length is a duration.

The third option is "entertainer". A user selects entertainer. Then the user must give a stage name. The user must write a short bio. The user must give a price per 30 minutes. Every entertainment order is done by exactly one entertainer. Every entertainer can choose which pizza restaurants to work for. For each pizza restaurant, the entertainer must give an availability by day. For example, the day is Monday, Tuesday, or Wednesday.
