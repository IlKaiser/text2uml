Project description:

Each web portal has a version number. Each web portal has a URL address. An example is "http://www.ebuntu-nrw.org". A web portal provides a catalog of buildings. The catalog shows the energy information of the buildings.

A building has a unique ID. A building has a name. A building has an energy class. The energy class is A, B, C, or D. A building has an address. A building has a year of construction. Each building is assigned to one user as the owner. The owner can add extra entries to the building.

Each extra entry has a name. An entry is one of two kinds. It can be textual information. Or it can be a floating point number with a unit. The unit is text that you can define freely.

The owner can release each extra entry publicly. This is optional. A public entry is also shown to non-registered visitors of that web portal.

Each building also has several images. One image is used as the profile photo. Each image is saved with a file name.

Visitors can register with a web portal. Then they become a user. A user has a unique user name. A user has an email address. A user has a password. During registration, the system checks that the user name is unique. The system also checks the email address. It does this by sending a confirmation link. In the meantime, an administrator sets up the user for the web portal. When these steps are done, the user is activated. The system then tells the user by email. The user can now log in.

After logging in, users can create buildings. They can manage entries for their buildings. They can comment on other users' buildings. All visitors to the site can search for buildings in the system. They use a full-text search.

Administrators are special users. An administrator also has an ID card number. This is stored with the normal user information. Administrators set up user accounts. Administrators delete comments.
