### Use Cases and Actors

- **Actors:**
  - Visitor
  - User
  - Administrator

- **Use Cases:**
  1. **Register User:** Visitor registers with a unique username and email.
  2. **Activate User:** System activates user after email confirmation.
  3. **Login:** User logs into the web portal.
  4. **Create Building:** User creates a new building entry.
  5. **Manage Entries:** User manages entries for their buildings.
  6. **Comment on Building:** User comments on other users' buildings.
  7. **Search Buildings:** Visitor searches for buildings using full-text search.
  8. **Set Up User Account:** Administrator sets up user accounts.
  9. **Delete Comment:** Administrator deletes comments.
  10. **Release Entry Publicly:** User releases additional entries publicly.

### Relationships

- **Generalization:**
  - `Entry` is generalized into `TextEntry` and `NumericEntry`.

- **Associations:**
  - `WebPortal` has a catalog of `Building`.
  - `Building` is assigned to a `User` as the owner.
  - `User` can create `Building` and `Comment`.
  - `Administrator` is a specialized `User`.
  - `NumericEntry` has an optional `Unit`.
